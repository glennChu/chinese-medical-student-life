# 一个中国医学生的一生

点击选择式叙事网页游戏（纯静态前端，可直接部署到 GitHub Pages）。

## 内容说明

本作是虚构与讽刺作品，不构成医学、法律或职业建议。不同地区与机构在 DRG/DIP、医保控费与管理实践上存在差异，游戏仅做概括性表达。

> 注：游戏中的 **院校层级、城市层级、医院层级** 都是叙事与数值平衡使用的**游戏化抽象**，不对应对任何真实学校、医院或地区的现实排名与价值判断。

## 本地运行

无需构建工具：

1. 直接双击 `index.html` 打开即可游玩；或
2. 在仓库目录启动静态服务（可选）：
   - `python -m http.server 8000`
   - 浏览器访问 `http://localhost:8000`

## 玩法简介

- 通过事件卡片和 2–4 个选项推进人生。
- 核心属性：健康、压力、经济状况、医术/临床能力、科研、人脉、医德/初心、法律风险。
- 新游戏直接从 **985 医学院报到日** 开始，中学与高考仅作为序章背景。
- 包含阶段推进（985 医学院→本科→研究生→规培/求职→住院/主治→高级分支→终局）。
- 多数关键行动带有成功/失败判定，成功率会根据当前属性实时变化，并在选项上显示“预计成功率”和主要影响因素。
- 支持属性门槛、前置 flag、随机事件、延迟后果、**必然后果队列**、判定分支与失败补救路线。
- 经济状况改为 **0–100 百分制**，代表与你的收入、支出、债务缓冲和生活成本相关的财务余量。
- 新增 **财务危机/破产** 机制：经济状况跌到危险边缘时会有分级提醒，跌到 0 会触发债务、搬迁、家庭援助或被迫离场等后续。
- 新增 **科室（specialty）系统**：儿科、急诊/重症、内科、外科、妇产、麻醉、口腔、眼耳鼻喉、影像/超声、病理/检验、精神科、全科/基层都拥有不同的 specialty profile 与后续事件池。
- 新增 **履历档案 / career path** 系统：本科平台、研究生平台、培养路径、城市层级、医院层级、单位类型与职称会持续记录并影响后续随机事件与职业流动。
- 重大抉择（如入学策略、考研/保研、规培去向、定科、关键职业机会）会有单独横幅、边框高亮与病历符号记录。
- 属性面板使用颜色状态条；健康/医德过低、压力/法律风险过高时会显示“警戒”或“危险”提示。
- 顶部会更醒目地显示 **年龄、医学生涯第几年、当前阶段、当前科室**，并把主线事件、随机事件、重试事件、必然后果事件用不同文字标签区分。
- `localStorage` 持久化：
  - 继续游戏
  - 重新开始
  - 清除存档
  - 历史结局与成就

## 判定机制

- 判定配置位于事件选项的 `check` 字段中，包含：
  - `baseChance`：基础成功率
  - `stats`：属性权重（正值提高成功率，负值压低成功率）
  - `minChance` / `maxChance`：成功率上下限
  - `success` / `failure`：成功与失败各自的目标、effects、flags、delayed、反馈与日志
- 当前实现的成功率公式：

```text
成功率 = clamp(
  baseChance + Σ((当前属性值 - 50) × 属性权重),
  minChance,
  maxChance
)
```

- 因此同一类判定会随着属性变化实时波动；例如医术、科研、人脉、健康、医德通常提高成功率，而压力、法律风险通常拉低成功率。

## 项目结构

- `index.html`：页面结构（首页、游戏页、结局页）
- `styles.css`：响应式视觉样式、动效与无障碍焦点
- `events.js`：事件与结局数据
- `check-system.js`：判定公式与概率计算逻辑
- `game.js`：状态机、存档、条件判定、成就、渲染
- `scripts/validate-events.js`：事件数据自检脚本

## 自检/测试

```bash
npm test
```

校验内容：
- 事件 ID 唯一
- 所有直接目标、随机目标、判定成功目标、判定失败目标都存在
- 所有 scheduled / forced event 目标都存在且不会直接自循环
- 非结局事件选项数在 2–4
- 至少存在可达结局
- 所有可达事件都能通向至少一个结局，避免新增分支卡死
- 判定配置合法（概率范围、上下限、属性名称）
- money 全量保持在 0–100 新量纲内，旧存档 money 迁移到百分制
- specialty 列表与 profile 字段完整，每个科室至少有 3 个相关事件/机会
- 关键 flags 既有来源，也有后续消费位置
- UI 中当前科室、年份横幅、重大抉择标签与 reduced-motion 处理存在
- 按 specialty 批量模拟，验证多种结局可达，财务危机不会压倒所有正常结局
- 轻量概率测试：属性变化会影响成功率，且成功率会被上下限夹住
- 事件总数与结局总数满足要求

## 启用 GitHub Pages

仓库已包含 `.github/workflows/pages.yml`：

1. 在 GitHub 仓库 **Settings → Pages** 中将 Source 设为 **GitHub Actions**。
2. 推送到 `main` 后会自动运行 `Deploy static game to Pages`。
3. 部署成功后可在 Actions 日志或 Pages 设置页查看公开地址。

# 一个中国医学生的一生

点击选择式叙事网页游戏（纯静态前端，可直接部署到 GitHub Pages）。

## 内容说明

本作是虚构与讽刺作品，不构成医学、法律或职业建议。不同地区与机构在 DRG/DIP、医保控费与管理实践上存在差异，游戏仅做概括性表达。

> 注：游戏中的 **院校层级、城市层级、医院层级** 都是叙事与数值平衡使用的**游戏化抽象**，不对应对任何真实学校、医院或地区的现实排名与价值判断。

## 本地运行

无需构建工具：

1. 直接双击 `index.html` 打开即可游玩；或
2. 在仓库目录启动静态服务（可选）：
   - `python -m http.server 8000`
   - 浏览器访问 `http://localhost:8000`

## 玩法简介

- 通过事件卡片和 2–4 个选项推进人生。
- 核心属性：健康、压力、经济状况、医术/临床能力、科研、人脉、医德/初心、法律风险。
- 新增 **体能/应急自保** 属性：用于体现跑步、力量训练、防身演练、夜班透支后的体能变化，以及极端场景中的撤离、自保与团队协作能力；它不是鼓励斗殴的数值。
- 新游戏直接从 **985 医学院报到日** 开始，中学与高考仅作为序章背景。
- 包含阶段推进（985 医学院→本科→研究生→规培/求职→住院/主治→高级分支→终局）。
- 多数关键行动带有成功/失败判定，成功率会根据当前属性实时变化，并在选项上显示“预计成功率”和主要影响因素。
- 支持属性门槛、前置 flag、随机事件、延迟后果、**必然后果队列**、判定分支与失败补救路线。
- 经济状况改为 **0–100 百分制**，代表与你的收入、支出、债务缓冲和生活成本相关的财务余量。
- 新增 **财务危机/破产** 机制：经济状况跌到危险边缘时会有分级提醒，跌到 0 会触发债务、搬迁、家庭援助或被迫离场等后续。
- 新增 **科室（specialty）系统**：儿科、急诊/重症、内科、外科、妇产、麻醉、口腔、眼耳鼻喉、影像/超声、病理/检验、精神科、全科/基层都拥有不同的 specialty profile 与后续事件池。
- 新增 **科室体验章节（3/3）**：选定科室后启动专属章节，从该科 ≥5 个独立专属事件中随机抽取，单局保证触发 ≥3 个不重复科室事件，UI 显示“科室体验 1/3、2/3、3/3”进度标签，完成后自动返回主线；存档迁移与继续游戏会保留进度。
- 新增 **履历档案 / career path** 系统：本科平台、研究生平台、培养路径、城市层级、医院层级、单位类型与职称会持续记录并影响后续随机事件与职业流动。
- 新增 **上一次选择结果卡片**：每次选择后会在下一回合“时间/重大事件信息”之后、当前事件正文之前，展示一张独立的结果叙事卡片（`aria-live="polite"`），统一呈现普通选项、判定成功/失败、重试、必然后果与履历变化的结果文字，并用**成功/失败/中性/履历变化/必然后果**等文字标签区分（不仅靠颜色）。刷新或继续游戏后结果卡仍会恢复；出现新结果时替换旧结果。
- 新增 **选择按钮定性影响预览**：自动分析选项的 `effects`、判定成功/失败方向、`yearDelta`、`delayed`/`scheduledEvents` 与履历变化，生成“预计影响：医术明显提升｜健康下降｜压力上升”一类的简短提示；判定类选项会额外提示成功/失败的大致方向（不泄露具体概率）；高经济成本、健康成本、法律风险、履历锁定选项会有文字警告；支持用 `impactHint` 字段人工覆盖自动生成结果。
- 新增 **恋爱/婚姻/下一代保底机制**：若到 32 岁仍未进入伴侣关系（且未选择主动单身/不婚/丁克），会触发一次可选的关系随机事件（不强迫恋爱）；30 岁后有伴侣但未结婚会有结婚保底；33 岁后已婚但未生育/领养会有下一代入口保底。恋爱类随机事件在尚未进入家庭线时权重更高，避免被 300+ 随机事件稀释。
- 新增 **恋爱状态机**：关系按 `single → met → interested → dating → committed → cohabiting → engaged_or_discussing_marriage → married_or_long_term_partner` 推进，不允许直接跳级；支持分手回到单身、重逢再进入、现实议题/同居磨合与“暂缓生育后再次讨论”。
- 恋爱、婚姻、家庭相关文本统一使用 **性别中性** 表述（如“对方”“伴侣”），避免把玩家锁进固定性别叙事。
- 新增 **地市/县域/基层医院区域章节（regionalChapter）**：在地市中心/强二甲、普通二甲、县域/基层医院工作时，会进入类似科室章节的 5/5 区域体验进度，覆盖转诊边界、资源限制、远程会诊、人才补贴、留人难与扎根/离开抉择。
- 新增 **经济自由** 终局：中后期若财务、年龄、风险条件合适，可选择完全退休、半退休教学/公益门诊，或继续工作但只做真正想做的部分。
- 医术、科研、人脉的每次收益统一走 **按属性独立分级的边际递减**（含小数进位机制，避免临界值附近的数值跳变）：70 分后开始衰减，85 分后显著衰减，95 分后只有少数高代价里程碑事件（单次收益 ≥6）能继续推高数值，不是硬性封顶。
- 重大抉择（如入学策略、考研/保研、规培去向、定科、关键职业机会）会有单独横幅、边框高亮与病历符号记录。
- 属性面板使用颜色状态条；健康/医德过低、压力/法律风险过高时会显示“警戒”或“危险”提示。
- 顶部会更醒目地显示 **年龄、医学生涯第几年、当前阶段、当前科室**，并把主线事件、随机事件、重试事件、必然后果事件用不同文字标签区分。
- `localStorage` 持久化：
  - 继续游戏
  - 重新开始
  - 清除存档
  - 历史结局与成就

## 判定机制

- 判定配置位于事件选项的 `check` 字段中，包含：
  - `baseChance`：基础成功率
  - `stats`：属性权重（正值提高成功率，负值压低成功率）
  - `minChance` / `maxChance`：成功率上下限
  - `success` / `failure`：成功与失败各自的目标、effects、flags、delayed、反馈与日志
- 当前实现的成功率公式：

```text
成功率 = clamp(
  baseChance + Σ((当前属性值 - 50) × 属性权重),
  minChance,
  maxChance
)
```

- 因此同一类判定会随着属性变化实时波动；例如医术、科研、人脉、健康、医德通常提高成功率，而压力、法律风险通常拉低成功率。

## 历史原型事件与虚构边界

- 首页提供 **“历史原型事件（含真实人物姓名）”** 开关，默认关闭；关闭时仅触发复合虚构化版本，打开后才可能遇到带真实姓名的历史原型版本。
- 李文亮医生相关链条采用克制写法，只参考公开事实框架中的“同行提醒、遭遇训诫式限制、后续程序不当被纠正的讨论”这一层，不把真实人物写成神话英雄，也不消费死亡。
- 韩杰医生相关链条严格使用 **“二审裁定生效后申诉/申请再审”** 的表述；游戏内若出现改判，只会以 **架空 / 虚构 / alternate-history** 分支明确标注，**不代表现实公开结果**。
- 两条链默认都以复合虚构角色出现，讽刺对象是信息迟滞、程序困境、形式主义和职业压力，而不是患者、家属或现实个体。

## 体能/应急自保与暴力风险

- 体能/应急自保系统服务于“先撤离、先报警、先保护患者和自己”的设计目标。
- 暴力风险事件里，更稳妥的选项始终是撤离、留痕、呼叫安保/警方、团队协作与环境控制；高体能只能略微降低受伤概率，**不能**把风险变成“值得硬顶”的鼓励。

## 项目结构

- `index.html`：页面结构（首页、游戏页、结局页）
- `styles.css`：响应式视觉样式、动效与无障碍焦点
- `events.js`：事件与结局数据
- `check-system.js`：判定公式与概率计算逻辑
- `game.js`：状态机、存档、条件判定、成就、渲染
- `scripts/validate-events.js`：事件数据自检脚本

## 自检/测试

```bash
npm test
```

校验内容：
- 事件 ID 唯一
- 所有直接目标、随机目标、判定成功目标、判定失败目标都存在
- 所有 scheduled / forced event 目标都存在且不会直接自循环
- 非结局事件选项数在 2–4
- 至少存在可达结局
- 所有可达事件都能通向至少一个结局，避免新增分支卡死
- 判定配置合法（概率范围、上下限、属性名称）
- money 全量保持在 0–100 新量纲内，旧存档 money 迁移到百分制
- specialty 列表与 profile 字段完整，每个科室至少有 5 个独立专属事件，基础候选 ≥3，`returnTo` 目标有效
- 关键 flags 既有来源，也有后续消费位置
- UI 中当前科室、年份横幅、重大抉择标签与 reduced-motion 处理存在
- 按 specialty 批量模拟，验证多种结局可达，财务危机不会压倒所有正常结局
- 轻量概率测试：属性变化会影响成功率，且成功率会被上下限夹住
- 事件总数与结局总数满足要求
- **高收益代价覆盖**：所有单次 `skill`/`research`/`network` 增益 ≥5 的普通分支与判定失败分支，必须至少伴随 health 下降/stress 上升/money 下降/ethics 下降/legalRisk 上升/`yearDelta`/`delayed`/`scheduledEvents` 之一
- **晋升长链可达性**：副高细分 → 主任医师职称评审 → 科室负责人竞聘/外部引进 全链具名事件（21 个）全部存在且从开局可达，相关结局可达数 ≥3
- **转行/私立路线可达性**：早期经济压力、转行网关与私立/国际部/行业/运营/科普等路线事件全部可达；正向结局与失败结局（试用期淘汰、失业、财务危机）各 ≥3 个可达；失败后存在 ≥2 条再就业/恢复路线
- **幽默/讽刺文案密度抽查**：对全部主线与随机事件正文及结果文案做关键词密度统计，要求 ≥15%
- **固定种子 2,400 局批量模拟**（`BULK_SIM_SEED=20260902`），统计并断言：
  - `skill`/`network` 的均值、中位数、P90、P95、95+ 比例（目标 6%–14%）、100 分比例（要求极低）
  - 伴侣关系达成率（目标 35%–55% 附近容差 30%–60%）、下一代入口达成率（目标 20%–35% 附近容差 15%–40%）
  - 科室体验 3/3 总体与分科室达成率

## 启用 GitHub Pages

仓库已包含 `.github/workflows/pages.yml`：

1. 在 GitHub 仓库 **Settings → Pages** 中将 Source 设为 **GitHub Actions**。
2. 推送到 `main` 后会自动运行 `Deploy static game to Pages`。
3. 部署成功后可在 Actions 日志或 Pages 设置页查看公开地址。
